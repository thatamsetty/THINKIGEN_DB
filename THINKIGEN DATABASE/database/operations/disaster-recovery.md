# Disaster Recovery

DR must protect the Organization database boundary and preserve historical ERP data.

The runbook must define:
- failure scenarios;
- recovery target;
- RPO;
- RTO;
- restore sequence;
- application reconnection;
- authorization validation;
- data integrity validation;
- communication/escalation;
- post-recovery verification.

Exact RPO/RTO values must be supplied by the business/operations owner; Cursor must not invent them.
